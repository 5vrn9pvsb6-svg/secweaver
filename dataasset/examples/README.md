# DataAsset Field Reference Examples

**Languages:** English (this page) | [简体中文](README.zh-CN.md)

This directory holds **non-production** field reference assets. Use them when onboarding a new data source to see which columns the platform supports and how they should be named.

## Files

| File | Description |
|---|---|
| [`reference-assets.json`](reference-assets.json) | **Single merged asset** `asset-example-all-fields`: `schema.fields` is the deduplicated union of the field sets for every `asset_type` in the public Schema |
| [`connectors/`](connectors/) | Non-production example connectors for new connector types or copy-paste templates; not included in the production `catalog.json` |
| [`hosts/`](hosts/) | Sanitized internal host inventory templates (inactive; not in demo registry) |
| [`networks/`](networks/) | Sanitized network zone templates (inactive; not in demo registry) |

## Structure

The following is a structural sketch; copy complete data from the linked JSON file:

```text
{
  "version": "2.0",
  "asset": { "...": "Complete asset JSON you can copy directly into dataasset/assets/" },
  "_derived": {
    "fields_by_asset_type": { "waf_alert": ["..."], "..." },
    "correlation_keys_by_asset_type": { "..." },
    "all_correlation_keys": ["..."]
  }
}
```

- **`asset`**: merged full-field asset (`field_aliases` already merged)
- **`_derived`**: per-`asset_type` field subsets and derived correlation keys (read-only index; do not write into production assets)

The merged asset's `asset_type` is fixed to `linux_syslog` (JSON Schema requirement only). When onboarding a real source, change it to the correct type and **remove** irrelevant `fields`.

## Field sources

Generated by [`../../src/dataasset/build_field_reference.py`](../../src/dataasset/build_field_reference.py) from:

1. [`../configure/evidence-minimum-fields.json`](../configure/evidence-minimum-fields.json)
2. [`../assets/correlation-matrix.json`](../assets/correlation-matrix.json)
3. Common source field names per type (`ip`, `host_name`, `trace_id`, etc.)

## Usage

```bash
# Regenerate after evidence / matrix changes
python3 src/dataasset/build_field_reference.py
```

When onboarding a new source:

1. Open `reference-assets.json` → copy the `asset` object
2. Trim `schema.fields` using `_derived.fields_by_asset_type.<your_type>`
3. Update `asset_id`, `asset_type`, `connector_id`, `query_template_ids`, `status`
4. Write to `dataasset/assets/`

**Do not** add `asset-example-all-fields` to production `bundles`.

## Coverage contract

The authoritative type set is `asset_type.enum` in [`data-asset.schema.json`](../schema/data-asset.schema.json), not a manually maintained list or count. Unknown types in the minimum-field specification fail generation. Types without a dedicated specification use baseline and common source fields, not an exhaustive vendor schema. The matrix derives correlation keys; it does not populate source columns. Regenerate after Schema, field-specification, or generator changes and run `python3 -m unittest tests.test_field_reference`.
