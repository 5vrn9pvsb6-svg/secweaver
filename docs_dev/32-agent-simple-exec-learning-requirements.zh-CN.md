# Agent 简化自学习白名单方案

后续 0.3.82 文件事件扩展见[文件学习需求](34-agent-simple-file-learning-requirements.zh-CN.md)，
本文的“其他事件类型”边界描述针对 0.3.81。

**语言：** [English](32-agent-simple-exec-learning-requirements.md) | 简体中文（本文）

日期：2026-10-08。状态：用户已确认，Agent 0.3.81 源码已实现；尚未打包部署。
用户已明确的核心规则：学习阶段，`listener_process`、`pid_name`、`exe`、
`command_line` 四个字段完全相同的事件，在一个小时内出现 5 次，进入白名单并立即过滤。
本文件把这条规则细化为可验收的需求；默认学习一天，但过滤不再等待学习期结束。
范围、边界与迁移见[模块架构](33-agent-simple-exec-learning-architecture.zh-CN.md)；
安装、恢复和服务端版本前提见[使用指南](../src/tools/secweaver-agent/docs/behavior-learning.zh-CN.md)。

同一规则现已扩展至 Windows 相关事件，当前跨平台范围以
[0.3.83 统一简化需求](36-agent-unified-simple-learning-requirements.zh-CN.md)为准。

## 1. 核心规则

同一设备、同一 exec 数据流中，使用以下四元组判断是不是相同行为：

```text
(listener_process, pid_name, exe, command_line)
```

四个字段必须逐字相同；不做正则、通配、忽略大小写、参数模板化或空白折叠。
使用有边界的结构化编码生成本地指纹，不能直接拼字符串造成组合碰撞。
设备/数据流用于隔离名单，不增加第五个行为匹配字段。

PID、PPID、listener PID、UID、TTY、CWD、inode、镜像哈希、cgroup、父命令、
进程启动时间、成功/失败标记、后端名称都不参与这套行为匹配，也不作为额外入名单门槛。
`pid_name` 是进程名称，不是数字 PID；PID 不同的同一种重复执行可以累计。

## 2. 一小时内出现 5 次

使用**滚动 60 分钟窗口**，不按整点分桶。
每次同一行为到来，移除超过 60 分钟的记录，再增加本次次数。
窗口内累计到第 5 次就进入本次学习生成的白名单并立即过滤；不需要再跨小时或等待 6 小时。
恰好相隔 60 分钟视为窗口内，超过则不计入。

计时使用实时采集路径接收完整事件的时间；历史补采不训练首日名单。
一次真实执行只算一次：audit 的 SYSCALL/EXECVE/PATH/PROCTITLE 拼接后是一个事件，
同一源事件重读/重试不重复计数；5 次不同执行恰好四字段相同，才是所需的 5 次。

| 事件时间 | 四字段 | 结果 |
| --- | --- | --- |
| 10:05、10:15、10:25、10:35、10:55 | 相同 | 10:55 入名单，从第 5 次起计数摘要、不输出原文 |
| 10:50、11:00、11:10、11:20、11:40 | 相同 | 11:40 入名单并立即过滤，跨整点无影响 |
| 10:00、10:10、10:20、10:30、11:01 | 相同 | 11:01 时只有 4 次，不入名单 |
| 同一事件被重复读取 5 次 | 相同 | 去重后只算 1 次 |
| 5 次事件中有一次 command_line 不同 | 其他三字段相同 | 分成两个行为，分别计数 |

## 3. 学习期与过滤生效

默认仍从安装后首次成功启动采集开始学习一天，停机和明确采集故障期间不计有效学习时间。
学习和过滤同时进行：未入名单的行为保留原文并累计次数；第 5 次满足条件、
成功加入名单后，该次及后续相同事件不再逐条输出原文，转为计数摘要。
前 4 次已经输出的原文不追溯删除，也不重复计入过滤摘要。
已入名单的行为不需要再次满足每小时 5 次，即使后续频率下降仍按精确匹配过滤。
入名单失败或计数摘要故障时保留原文，不能只因计数达到 5 就丢弃事件。

学习期内仍继续为其他行为建立名单。学习结束只冻结新增名单，已有名单继续过滤；
名单外行为正常输出，执行期不自动吸收新的行为。

```text
学习阶段：名单外 -> 原文 + 滚动一小时计数
          满 5 次并成功入名单 -> 当次起计数摘要
          已在名单中 -> 计数摘要；继续学习其他行为
学习结束：冻结新增名单；已有名单继续过滤
之后运行：命中名单 -> 计数摘要；名单外 -> 原文，不再自动入名单
```

学习结束时名单为空，显示“学习完成，无可过滤行为”，继续输出原文；
空名单本身不显示“已降级”，真正输入/状态/输出故障另行诊断。
`shadow` 仍表示保留全部原文；`disable` 仍表示关闭学习过滤；
`preserve` 仍保留已有启用选择，不因升级静默启用此前关闭的机器。
正常学习阶段只要名单非空、过滤已启用且运行正常，`filtering_active=true`；
不能再仅因阶段是 learning 就上报 false。`shadow`、关闭或故障退回原文时为 false。

## 4. 取消哪些旧规则

| 旧规则 | 新方案 |
| --- | --- |
| 至少 3 个健康小时桶 | 取消 |
| 首次/末次跨度至少 6 小时 | 取消 |
| 父进程必须是监听根的直接父关系 | 不再作为白名单资格；监听归属仍由原采集器确定 |
| 父子 cgroup 相同且包含 .service | 不再作为白名单资格 |
| UID/有效身份一致、CapEff 必须为零 | 不再作为白名单资格 |
| 必须实时反查存活 /proc 实例及文件 inode/SHA256 | 不再作为白名单资格 |
| 按程序名排除 bash/java/curl/ssh 等工具 | 不再作为这套 exec 入名单门槛 |
| 父/子完整身份大上下文指纹 | 改为四字段精确指纹 |

重复的 bash/curl/ssh 等执行也可满足本规则。重复攻击可能具有同样四字段，
因此入名单不意味着安全；这套名单的用途是减量。其他数据流的登录、认证、
持久化和风险告警不会因为 exec 命中名单而被一起过滤。

本次简化方案不再用旧学习期 P95 或跨小时统计增加命中门槛。
采集、进程树跟踪、日志轮转、摘要上传与故障恢复原文属于基础运行职责，继续独立工作。
它们不能重新把已取消的身份/祖先规则隐式加回入名单判断。

## 5. 字段质量与匹配边界

四字段缺失或命令已截断时保留原文，不拿缺失值/省略尾部生成自动白名单。
这是因为无法构造完整匹配键，不重新引入 /proc、UID 或服务资格校验。
audit 命令应优先使用完整 EXECVE；PROCTITLE 不得覆盖更完整的参数。

`command_line` 使用采集器规范化后的完整字段，按字符串精确匹配；
不同 argv 边界若被现有 command_line 序列化成相同字符串，按本规则视为相同。
本次不偷偷加入 argv 作为第五个匹配字段；该显示契约的歧义在实现设计时需记录。
匹配在原文脱敏前进行，本地状态只存不可逆指纹、必要的脱敏展示与计数。
不得保存完整口令/token；也不得用脱敏占位符把两个真实不同命令合并。

## 6. 数据流范围

四字段目前直接存在于 Linux audit/eBPF exec 标准事件，因此先以它作为明确的数据契约。
同一方案兼容两个后端，后端名称不参与匹配。
这不扩展监听发现、内核规则或事件归属范围。

Windows exec、文件、外连、PowerShell 风险事件并不都具有这四字段。
不能把空字段当通配、把 ParentImage 猜作真实 listener_process，
或把不同文件/目标地址用同一执行四元组一起免报。
本规则的跨平台/其他事件扩展需另外确定字段契约；当前修订没有改变它们的既有学习政策。

## 7. 运行体验与迁移要求

- 页面和 Doctor 显示：是否启用、学习开始/剩余时间、名单条数、是否正在过滤、故障原因。
- 说明策略应直接显示“一小时内相同四字段出现 5 次”，不要求用户理解小时桶/资格能力。
- 页面应允许同时显示“学习中”和“过滤已生效”，避免把两者误作互斥状态。
- 原来的复杂名单不能直接解释为新四字段名单，需要新策略标识和明确重新学习的迁移流程。
- 已启用学习的机器迁移时，尚未进入新名单的行为保留原文；新名单入选即过滤，
  不得无提示混用新旧指纹。
- 正常重启保留可读学习进度与名单；状态损坏、明确丢事件等仍优先保留原文并提示处理。
- 输入、状态或摘要写入故障不应伪装成正常减量；磁盘写失败仍需原输出模块处理。

0.3.81 用独立策略标识、带 HMAC 的入名单日志和检查点实施迁移；
先升级 Agent Server 至 0.6.0-rc.72、企业工作台至 0.6.0-rc.112，
再部署新 Agent，确保服务端接受并显示“学习中且正在过滤”的心跳。

## 8. 性能约束

学习热路径只做四字段编码/本地指纹、源 ID 去重、名单查找和最多 5 个近期时间点更新。
记录已达到阈值后无需保存一小时内每次出现的全部时间戳。
不为学习单独扫描 /proc、读取可执行文件、计算镜像 hash 或调用外部命令。
候选/名单与源去重必须有条数和字节上限；达到容量时保留原文，并显示可理解的容量原因。
资源故障不通过放宽匹配、隐藏未知事件或阻塞底层 reader 来处理。

## 9. 验收要点

1. 四字段相同而 PID/UID/父进程/cgroup/后端不同，仍累计同一行为。
2. 60 分钟内第 5 个不同事件入名单；超窗口、跨整点、重复源 ID 都按第 2 节处理。
3. 四字段任一变化计为新行为；缺失/截断不训练。
4. 正常学习期前 4 次保留原文，第 5 次成功入名单后立即过滤并计入摘要；
   已有名单继续过滤，其他行为继续学习，学习结束只冻结新增；shadow 始终保留。
5. 重复工具执行无需旧复杂资格；其他认证/持久化/风险数据流保持输出。
6. 空名单显示“学习完成，无可过滤行为”，源故障仍有单独原因。
7. 已有机器升级不混用旧名单；正常重启、状态损坏、容量满与计数摘要可观测。
8. 本地原文/名单/摘要与云端结果对照验证，包发布前按仓库规则升版。
9. 学习阶段已有生效名单时上报 filtering_active=true；摘要不重复计入前 4 次原文，
   低频后续仍命中名单；入名单失败/摘要故障保留原文并有诊断。

本轮实施源码、注释、回归测试及文档；未发布安装包或修改线上主机。
