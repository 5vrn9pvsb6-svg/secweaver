# Community 发布验收清单

[English / 简体中文](community-release-checklist.md)

面向发布维护者。用户的查询完整性、TLS 和脱敏要求见 [真实数据使用说明](../docs_user/community-release-and-data-safety.zh-CN.md)。

## 独立运行与发布

Community 包含 DataAsset、Skills、CLI、DataAsset Studio 和主机采集 Agent。
本地合成数据调查无需私有服务端。自建数据源需要用户自己的服务、只读账号与网络权限；
选择 SaaS SLS Proxy 时需要平台提供服务和凭证。发布归档不包含私有服务端或内部 Git 历史。

维护者从已经提交、工作区干净的版本运行：

```bash
make docs-check
make open-source-export OUTPUT=/tmp/secweaver-community.tar.gz
```

导出读取 `HEAD`，未提交修改（包括私有目录中的文档）会阻断导出。
不要为通过检查而删除未提交工作。CI 将演示输出写到临时目录，避免时间戳和本机路径
污染已跟踪示例。公开示例报告使用仓库相对路径；发布扫描拒绝示例报告中的用户主目录路径。
运行时调查报告可能仍有本地绝对路径，分享前需检查。

发布验收应包含：公开归档内的文档、SBOM、严格校验、测试、离线案例和 Studio 启动；
全新环境依赖安装；目标 Linux/Windows 的 Agent 服务升级测试；使用目标数据源的只读验收。
交叉编译不等于真实系统运行验收，Attack Lab 脚本语法检查不等于 Docker 实验执行成功。
私密漏洞报告入口以[安全策略](../SECURITY.zh-CN.md)为准，维护者必须在正式发布前配置可用渠道。


## 验收记录

导出脚本会在归档内运行发布扫描、文档检查、SBOM、严格资产校验、策略同步、公开 Python 测试和离线 demo，并在 demo 重写报告后再次扫描。发布扫描同时检查公开文档、Skill、样例、源码和测试夹具中的已知内部验收网段及常见本机工作区路径；真实验收主机必须改为文档地址，文件引用必须使用仓库相对路径或在运行时解析后才能进入归档。这些不能代替完整 CI 或真实系统验收。每次发布记录以下项目，不用“部分通过”代替全部通过：

| 项目 | 应记录的证据 |
|---|---|
| 来源与产物 | 已提交 commit、Community/Agent 版本、归档 SHA-256 |
| 自动门禁 | `make ci` 及归档验证的命令、退出码、日志；未运行项及原因 |
| 新手体验 | 全新环境安装、离线样例与 Studio 启动结果 |
| Agent 平台 | 实际 Linux/Windows 服务安装、升级、失败回滚的版本和记录 |
| 真实数据 | 经授权的只读验收范围、结果与缺口，不记录凭证 |

## 历史资料

内部 P0 验证报告不作为发行证明，也不随 Community 导出。Attack Lab 四篇案例仅作历史场景说明，当前验收以归档内合成样例、版本和测试记录为准。
