# Agent 行为学习与日志减量设计

**语言：** [English](30-agent-behavior-learning-design.md) | 简体中文（本文）

状态：设计方案，0.3.37 实现 Linux 子集，0.3.38 增加保守 Windows Sysmon 适配器。
设计日期：2026-09-23。当前行为与限制以[使用指南](../src/tools/secweaver-agent/docs/behavior-learning.zh-CN.md)为准。
实际支持范围与配置以[实现指南](../src/tools/secweaver-agent/docs/behavior-learning.zh-CN.md)为准。
下文保留完整目标设计：多层祖先资格、逐项管理、版本回滚及所有真实平台验收尚未完成；
示例 JSON 是目标契约，实际状态文件使用带 HMAC 的封装，默认位于 Agent data 目录。
源码更新不代表二进制已发布或部署。

## 1. 目标与关键决定

新安装默认开启学习模式：安装完成后，Agent 首次成功启动采集即自动进入学习，
无需管理员另行启用。默认从此时累计一天（24 小时有效观测时间），建立本机的稳定行为名单。
“安装后的第一天”不是等到次日零点；只解压或安装但尚未启动采集时不开始计时。
学习期结束后，名单外行为持续逐条输出；命中名单的正常行为不再逐条写入上传日志。
名单内行为仍被底层观察和计数，以维持进程树、检测变化并输出低频摘要。

学习名单是“允许减少日志的行为集合”，不是可信程序清单，也不是执行权限白名单。
本模式不阻止进程执行，不等同于恶意行为检测，更不保证被学习的主机没有失陷。

| 决策 | 设计 |
|---|---|
| 默认学习时长 | 24 小时健康观测时间，停机及明确丢事件期间不计时 |
| 学习期输出 | 原始事件全量输出，额外维护本地候选名单 |
| 初次自动生效 | 合格的重复行为在学习结束后自动生效，不要求逐项人工批准 |
| 未满足资格的行为 | 留作候选，不免报；“见过一次”不代表允许过滤 |
| 名单外行为 | 逐条输出，不在执行阶段自动吸收进名单 |
| 名单内行为 | 在频率范围内抑制原始输出，每 5 分钟输出计数摘要 |
| 始终采集事件 | 敏感操作、身份异常、失败、信息不完整和策略无法判定的事件 |
| 出错策略 | 停止过滤，恢复现有原始输出路径，并上报降级状态 |
| 旧安装升级 | 不自动启用；显式启用后才开始首次学习 |
| 新安装默认值 | enabled=true；安装后首次启动采集立即自动学习 24 小时，无需手动操作 |

## 2. 范围与现状

0.3.39 实现更新：Windows Sysmon 适配器还学习精确的合格内网外连，以及指定目录内普通 `.log`
创建，用 GUID 关联已观察到的 Event 1 身份。各类型独立指纹和摘要计数。认证/持久化/风险、
敏感/破坏性动作和快照仍受保护，Linux 非 exec 输出不变。当前范围、升级 generation 要求及
来源/上下文缺口以上方使用指南为准，下文更广泛的设计不等于当前已实现。

首期只覆盖 Linux 的 audit-port-execmon 中 exec 事件，适用于 audit 和 eBPF 后端。
已有内核能力探测和回退规则保持不变；更换后端不会自动信任不等价的基线。
Windows 0.3.38 使用独立的执行时 Sysmon GUID/SHA256/服务 token 语义，4688 仍全量输出；
真实 Windows 环境验收尚待完成。

原 Linux 首期的 file_op、敏感文件读取、认证、host_persistence、快照和运维健康事件不参与过滤。
因此“名单外才采集”准确含义是：仅对本模块合格的 exec 行为减少原始日志输出。

当前实现中 [audit 事件输出](../src/tools/secweaver-agent/pkg/auditportexecmon/audit_event.go)
和 [eBPF 事件输出](../src/tools/secweaver-agent/pkg/auditportexecmon/ebpf_events.go)
原有流程分别序列化并逐条写出；0.3.37 新增[学习适配器](../src/tools/secweaver-agent/pkg/auditportexecmon/learning.go)
和独立学习包。[配置结构](../src/tools/secweaver-agent/pkg/auditportexecmon/config.go)
通过 behavior_learning 接入首期实现。audit 压力控制仍是规则下发保护，不能代替输出减量。

用户提供的单机 24 小时样本共 159,668 条，其中 exec 158,242 条（约 99.1%）。
归属于 Java/MySQL 监听进程树的 exec 共 144,223 条（约 90.3%）。
listener_process 只标识归属服务，必须进一步看实际 exe、argv、父进程和身份。
本文不把这些进程名视为正常名单，也不承诺预设减量比例。

## 3. 数据流程与模块边界

处理顺序：

1. audit/eBPF 接收事件，完成事件拼接、自身行为排除与监听服务归属。
2. 更新 fork/exec/exit 进程树和进程生命周期，绝不因免报跳过这一步。
3. 提取后端中立的行为上下文，执行始终采集规则及资格判定。
4. 学习模块返回 emit、suppress 或 emit_with_context 决策及原因。
5. 输出原始事件、必要的祖先证据、聚合摘要或状态变更。
6. 原有轮转、磁盘保护和上传组件继续处理日志文件。

拟新增独立包 pkg/behaviorlearning，内部按 policy、fingerprint、learner、
matcher、store、summary 拆分职责；audit/eBPF 适配器只负责上下文转换。
不把规则写入通用 pkg/output；通用 writer 不具备事件语义，不能可靠判断免报。

接口输入为规范化事件、可信进程实例信息、单调时钟和当前健康状态。
返回结构化 Decision，不在热路径中调用网络、执行 shell 或等待远端批准。
只有学习模块拥有基线与计数状态；后端 reader 继续拥有采集和进程树状态。
Windows 已通过独立适配器接入，使用完整命令字符串和独立身份字段，不复用 Linux argv/UID 假设。

## 4. 状态机与计时

| 状态 | 输出行为 | 转移条件 |
|---|---|---|
| disabled | 原始输出 | 显式启用后进入 learning |
| learning | 原始输出，学习候选 | 健康观测达到 24 小时，进入冻结检查 |
| enforcing | 未知/异常原始输出，已知正常计数 | 基线有效且冻结检查通过 |
| degraded | 原始输出，停止新增免报 | 丢事件、状态损坏、资源不足或证据能力下降 |
| relearning | 原始输出，建立候选替换版本 | 显式重新学习；结束后原子替换基线 |

有效时间用单调时钟累计，状态落盘保存累计值。重启恢复学习进度，停机时间不算学习。
不使用“启动时间 + 24 小时”直接切换，系统时间前跳/回拨不能提前结束学习。
UTC 时间仅用于审计展示；进程内计时和限速不依赖 UTC。

学习期间 audit lost、eBPF lost samples 增长，reader/demux 故障，或必要上下文缺失时，
暂停有效计时并记录缺口。明确丢事件使当前学习周期不可自动晋级，需重新学习或人工复核，
不能只等待恢复就把不完整样本当作正常基线。
健康状态持续稳定 10 分钟后才恢复计时/匹配。程序只认可稳定、可验证的健康信号。

首次启动后达到 72 小时在线运行预算仍未完成学习时进入 degraded，停止候选增长并提示原因。
重启保留这一预算，停机不计入；墙上时间超过 72 小时另报进度提醒，不据此强制晋级。
无合格行为时保持原始输出，记录 baseline_empty，不为了满足期限强行生成名单。

正常重启加载同一设备、策略和指纹版本的冻结基线，不重新学习。
设备身份改变、基线不存在或损坏时回退原始输出并等待明确恢复/重新学习操作。
首次安装且从未开始学习时默认自动进入 learning；仅显式配置 enabled=false 才保持 disabled。
普通重启、覆盖安装和版本升级不得重置已有学习进度或基线；不能把运行中丢失基线误判成首次安装。

## 5. 行为指纹

“行为”必须是服务上下文中的执行，不是 listener_process 或单个 exe 名称。
指纹对确定性、带版本的结构编码后做本地 HMAC-SHA-256；长度前缀或规范 JSON
确保 argv 边界不丢失，例如两个参数不能与一个含空格参数混淆。

| 纳入指纹 | 说明 |
|---|---|
| 设备与策略范围 | device_id、本地策略 revision、fingerprint_version |
| 服务身份 | 监听根 executable 路径/摘要、监听地址/端口、可验证的 unit 或容器工作负载身份 |
| 父执行上下文 | 父 exe/摘要及父执行指纹，锚定同一服务；祖先无法解析时不免报 |
| 实际执行 | exe 路径/摘要、原始 argv 数组、cwd |
| 身份与会话 | uid/euid、gid/egid、auid、会话/TTY 分类；缺少必需字段即不免报 |
| 结果与能力 | success/exit、完整性标志、后端上下文能力版本 |

PID、PPID、audit_id、每次执行时间不作为跨次行为名单键，否则重复任务永远无法命中。
它们仍保留在原始证据与本地执行实例记录中。
进程实例键使用 boot_id + pid + start_time；同一个 PID 多次 exec 还需 exec 序号，
防止 PID 复用、同 PID 更换程序或跨启动周期造成错误归属。

服务重启可在 unit、程序、参数和其他条件完全一致时命中旧行为。
无法取得稳定服务/容器身份时不跨实例复用名单；容器 ID 改变默认视为新范围。
只有有明确工作负载映射时才允许跨容器复用，禁止仅凭 dockerd 归属合并不同容器。

默认参数精确匹配，不自动删除时间戳、数字、IP、端口、URL、脚本内容和随机字符串。
可变参数掩码只能作为明确、带版本的管理策略下发，不能由学习算法自行扩大匹配范围。
命令参数可能包含口令，HMAC 在脱敏前计算以区分实际行为；本地密钥不上传，
基线只保留指纹与脱敏样本。轮换密钥使原指纹失效，需重新学习，不能静默放宽匹配。

### 5.1. 一条名单究竟允许什么

一条记录只表示“这台设备上的这个服务，通过这个父执行上下文，以这组身份和会话，
执行这个文件版本、这组完整参数和工作目录时，允许减少原始日志”。
它不表示 java、mysqld、某个用户或某个目录下的全部行为可信。
也不是 auditctl 的内核规则白名单：名单命中不会删除监控规则，不会停止子进程跟踪。

下面是假设的正常业务：example-app.service 的 Java 进程每分钟直接执行一次
stat -- /var/lib/example/ready，检查普通业务文件元数据。
假设程序及父程序受控、身份完整、无敏感规则命中，并持续健康观测 24 小时，
才可能生成这一条。此例不是对 stat 的内置放行，也不是从真实主机提取的结果。

### 5.2. 冻结名单文件示例

以下是可读 JSON 形式的持久化契约草案，实际存储编码待实现确定。
尖括号内容是摘要占位符，正式值为完整的 64 位十六进制摘要，不能直接加载此例。

```json
{
  "schema_version": 1,
  "baseline_id": "baseline-example-001",
  "device_id": "device-example-001",
  "policy_revision": 1,
  "fingerprint_version": 1,
  "hmac_key_id": "local-key-001",
  "capability_profile": "linux-exec-context-v1",
  "learning": {
    "started_at": "2026-09-23T10:00:00+08:00",
    "completed_at": "2026-09-24T10:00:00+08:00",
    "healthy_seconds": 86400,
    "known_event_loss": false
  },
  "entries": [
    {
      "entry_id": "entry-example-001",
      "behavior_fingerprint": "<HMAC-SHA-256: complete canonical behavior>",
      "match": {
        "service_context_hmac": "<HMAC-SHA-256: verified service context>",
        "parent_context_hmac": "<HMAC-SHA-256: anchored parent execution>",
        "execution_hmac": "<HMAC-SHA-256: executable identity, exact argv, cwd>",
        "identity_hmac": "<HMAC-SHA-256: credentials and session classification>",
        "result_hmac": "<HMAC-SHA-256: exec syscall result and completeness>"
      },
      "sample_redacted": {
        "listener_process": "java",
        "service_unit": "example-app.service",
        "listener_address": "0.0.0.0",
        "listener_port": 8080,
        "parent_exe": "/opt/example/jdk/bin/java",
        "exe": "/usr/bin/stat",
        "argv": [
          "stat",
          "--",
          "/var/lib/example/ready"
        ],
        "cwd": "/var/lib/example",
        "uid": 1001,
        "euid": 1001,
        "gid": 1001,
        "egid": 1001,
        "auid_state": "unset",
        "session_class": "service_noninteractive",
        "has_tty": false
      },
      "learned": {
        "observed_count": 1440,
        "distinct_hours": 24,
        "first_seen": "2026-09-23T10:00:00+08:00",
        "last_seen": "2026-09-24T09:59:00+08:00",
        "p95_count_per_5m": 5
      },
      "promotion": {
        "origin": "automatic_learning",
        "eligible": true
      },
      "action": {
        "type": "suppress_original_with_summary",
        "rolling_window_seconds": 300,
        "max_events_per_window": 15,
        "anomaly_emit_seconds": 600,
        "idle_expiry_days": 30
      }
    }
  ]
}
```

| 字段组 | 用途与修改规则 |
|---|---|
| 顶层设备/策略/密钥/能力版本 | 限定这份名单适用的设备与语义；不兼容就恢复原始输出 |
| behavior_fingerprint | 热路径精确匹配键，对第 5 节全部必需字段计算；不能只匹配其中一部分 |
| match.*_hmac | 分组诊断身份、服务、参数等哪一组改变；不用于模糊匹配，也不存明文敏感参数 |
| sample_redacted | 供管理员查看的脱敏代表样本；绝不参与授权匹配，手改样本不能扩大过滤范围 |
| learned | 冻结时的学习证据，用来解释为何晋级；不会被运行期计数覆盖 |
| promotion | 来源与冻结时资格；运行时仍先检查始终采集规则，不能仅凭 eligible=true 免报 |
| action | 命中后的减量及频率边界；超过边界继续输出，不执行或阻止任何进程 |

完整匹配输入还包括样本中未展开的根/父/子程序摘要、服务启动参数、父执行指纹和能力标志。
指纹计算使用真实 argv 和字段值，脱敏样本不是其可逆表示；不能从样本重新构造原指纹。
分组 HMAC 使用不同的域标识，避免把某一组摘要误用为其他组。
未知字段和值与“已确认 unset”不同，例如 audit 明确给出的 unset auid 可归类为
service_noninteractive；无法取得 auid/会话状态则不能生成合格匹配上下文。

success/exit 指 exec 系统调用结果，不是子程序最终退出码。
执行成功并不证明业务命令运行正常；最终退出结果只有后端明确采集时才可另行使用。
首期若要求的 euid/gid、执行文件身份或父链当前后端无法提供，必须先补齐上下文，
不能把缺失值填成 0 或复用 PID 当前信息来获得免报资格。

### 5.3. 哪些变化会命中，哪些不会

| 下一次观察 | 处理 |
|---|---|
| 相同服务、父执行上下文、文件版本、完整参数、身份，只有子 PID/时间改变 | 在频率范围内命中；计数并生成摘要 |
| 同一个 Java 服务执行 stat，但参数目标改成另一个文件 | 指纹不同，原始输出 |
| Java 执行 sh -c 'stat -- /var/lib/example/ready' | shell 命中始终采集；不是示例中的直接执行 |
| Java 执行 curl、其他下载工具或未知程序 | 始终采集规则或名单未命中，原始输出 |
| 相同命令改由 sshd 会话发起 | 服务/父链/会话不同，原始输出 |
| 相同命令由 uid=1001 改为 uid=0，或发生提权 | 身份改变，原始输出 |
| 同一路径的 stat 或 Java 程序文件发生替换 | 文件身份待验证或摘要改变，原始输出 |
| 参数只有日期、随机数或 URL token 改变 | 默认精确匹配，原始输出，不自动忽略变化 |
| 服务正常重启，身份、启动参数及全部稳定上下文一致 | 完成新实例校验后可命中；PID 复用本身不能继承资格 |
| 缺少 argv、祖先或必要身份，或来自能力不等价的后端 | 原始输出并记录不能匹配的原因 |
| 命中示例项，但滚动 5 分钟内出现第 16 次 | 第 16 次起恢复原始输出，并进入 10 分钟异常输出期 |

这里的 15 来自 max(10, 3 × P95=5)。不是每条名单都固定允许 15 次。
匹配顺序仍是先执行强制保留与完整性检查，再查名单，最后核对频率；
匹配项存在不能越过前置检查。

### 5.4. 学习候选、正式名单和运行状态分开保存

- candidates：学习期间的有界候选及次数、小时桶、首末时间和资格原因。
  例如 repeated_eligible、insufficient_occurrences、insufficient_span、
  always_emit_shell、incomplete_identity；原因码是草案。
- baseline：24 小时结束时通过条件的不可变名单。学习见过但不合格的行为不会放入 entries。
  正常执行阶段不会因未知命令重复很多次就自动追加。
- runtime：每条基线的最近命中时间、滑动计数、异常输出截止时间、摘要计数和证据缓存。
  高频变化只更新内存，由有界检查点落盘，不逐事件重写 baseline。
- manifest：当前基线引用、学习进度和状态标记，按第 8 节原子提交。
  本地 HMAC 密钥单独保管；摘要校验不是远程策略签名，不能混用。

重启时若最近的频率状态不完整，至少恢复一个完整滚动窗口的原始输出并重建计数；
不能把重启当作清空计数后立即获得新的免报额度。
未完成的异常输出期恢复时从保守剩余时长继续；无法确定则重新计满该保护期。
名单文件或关键状态丢失按 degraded 处理，不自动重新信任所有观察到的行为。

### 5.5. 管理员看到的名单与减量效果

管理界面/导出应按“服务 → 实际命令”展示，每项给出脱敏命令、身份、学习次数、
时间跨度、晋级/不晋级原因、频率上限、最近命中和节省原始日志条数。
展示字段与执行键分离，不提供“白名单整个 Java/MySQL”快捷选项。
操作采用撤销单项、停止过滤、显式重新学习；不能直接编辑脱敏样本改变匹配。

上述每分钟一次的例子，学习日保留 1,440 条原始 exec；稳定执行日最多产生
288 条正常 5 分钟摘要，另有健康、状态和必要的祖先补发日志。
这是该条行为的示例，不是整机承诺。每个窗口只有一次命中的低频行为，
用一条摘要替代一条原始事件并不节省条数；必须按真实总字节衡量收益。
若父链中的常见 shell、变化参数或不完整身份使事件不合格，它们仍输出，
不能为了得到预设比例把资格条件放宽。

## 6. 候选晋级与始终采集规则

所有可解析的 exec 可计入候选统计，但自动免报必须同时满足：

- 同一精确指纹至少出现 5 次，覆盖至少 3 个不同小时桶，首末出现间隔至少 6 小时。
- 执行成功，身份、服务归属、祖先链和参数完整。
- 未命中始终采集规则；执行程序及父程序身份均可校验。
- 所需文件身份未变化，学习周期没有明确丢事件或不可解释的观测缺口。
- 冻结时再次校验策略版本、资格和资源预算，通过后一次性提交不可变基线版本。

这些阈值是默认提案，低频任务、每日任务、首次部署的新命令仍输出。
一天不能覆盖周任务和所有业务路径；不能通过自动持续学习来消除这些正常告警。
达到次数/时间阈值只是重复性证据，不是安全证明：已经被入侵的主机仍可能污染名单。
建议在正常业务窗口安装；新安装仍默认自动学习，不等待人工批准。
若主机正在处置入侵，可显式禁用学习，恢复正常后再启动学习；保留学习期原始日志和可审阅样本。

以下事件始终输出，且优先级高于自动名单和人工名单：

- file_op、敏感路径操作、认证和持久化变更，以及首期不支持过滤的其他类型。
- 执行失败、权限/身份变化、未知用户、未知会话状态、命令截断或归属不完整。
- shell/解释器执行命令文本或脚本、交互会话、远程执行/下载/传输工具等首期保守规则。
- 临时目录、可写非受控目录、已删除文件、memfd 程序，以及文件身份未完成验证的执行。
- 已命中现有高风险行为策略的事件；匹配器故障也必须输出。

工具名称规则不是完整威胁检测。实现需说明路径、文件身份及规则版本，防止改名绕过。
首期脚本/解释器不自动免报，因为“同一路径 + 同一参数”不能证明脚本或载荷没变化。
不得直接假设服务端 Skills 的风险引擎已在 Agent 上运行；需要定义独立的小型本地
始终采集规则集并做契约测试。未实现的风险判断不算已覆盖。

程序摘要不得逐事件重新读取整个文件。异步有界 worker 校验只读文件描述符，
记录 dev/inode/size/mtime/ctime 及执行可见身份；缓存失效期间输出原始事件。
受控文件身份变更监听加周期复核提供失效信号；无法绑定执行对象与所校验对象时不免报。
元数据缓存不是对抗 root 篡改的完整性保证，主机 root 已失陷超出本地基线信任边界。
外部配置、动态库、网络输入等未建模变化仍是残余风险，不宣称指纹等价于程序全部语义。

## 7. 名单执行、频率异常与取证

名单冻结后，查找顺序是：始终采集 → 字段完整性 → 文件身份 → 精确名单 → 频率范围。
任一步无法判断即输出原始事件。未知行为不会因多次重复而自动入名单。
名单设定 30 天未命中失效；失效或撤销后重新输出，重新学习必须显式发起。

每条基线记录学习期 5 分钟计数分布（包括零值桶）。
拟采用每个滚动 5 分钟上限 max(10, 3 × 学习期计数 P95)，以有界时间桶实现，
不能用固定窗口边界放过双倍突发。阈值是减量保护，不是攻击判定。
一旦超过上限，本次及该行为随后 10 分钟的事件原样输出，并立即生成频率异常摘要；
此前免报次数仍保留在摘要里。低速重复恶意行为可能不越阈值，不能保证自动发现。

被免报父进程的子进程仍被跟踪。如果子进程未知或高风险，输出子事件，
并从有界本地上下文缓存补发相关祖先 exec 作为 context_only 证据。
补发证据必须引用真实 event_id，保留原发生时间，不能合成不存在的父命令。
缓存缺失/淘汰/重启时明确 ancestry_context_missing，不得声称完整攻击链。
只有上下文已成功缓存才允许免报；上下文缓存容量不足时恢复该事件原始输出。

上下文默认保留最长 24 小时，受内存预算约束，先清理已退出实例的旧记录。
保留无法保证任意长时间后的完整溯源；如要求完整取证，应使用 full 模式或启用
单独的本地原始事件归档。后者必须有磁盘配额和保留期，不能继续被上传器通配采集。

正常摘要按每个命中指纹每 5 分钟最多一条，仅有命中才输出。
关闭、策略切换时尽力刷新；崩溃/断电不保证最后一个窗口计数完整，恢复时标注缺口。
未知事件不采样，不使用总量硬限额静默丢弃。
云端仍会有少量健康和摘要日志，不会只有名单外的日志。

## 8. 配置与持久化草案

以下 JSON 仅为未来 audit-port-execmon 模块配置中的拟新增片段，不是当前可用配置：

```json
{
  "behavior_learning": {
    "enabled": true,
    "learning_duration_seconds": 86400,
    "learning_online_deadline_seconds": 259200,
    "activation": "auto_eligible",
    "event_types": ["exec"],
    "min_occurrences": 5,
    "min_distinct_hours": 3,
    "min_span_seconds": 21600,
    "summary_interval_seconds": 300,
    "baseline_idle_expiry_days": 30,
    "max_baseline_entries": 10000,
    "max_candidate_entries": 20000,
    "memory_budget_mb": 64,
    "state_budget_mb": 64,
    "on_error": "emit"
  }
}
```

duration 建议允许 1 小时至 7 天；生产默认 24 小时。deadline 不得小于 duration。
未知字段、冲突预算、非法阈值应拒绝策略激活并保持先前有效策略；
首次配置无有效策略时输出原始事件并报告配置错误，不因减量策略错误停止主采集器。
首期 event_types 只允许 exec，on_error 只允许 emit。

拟持久化位置为 Agent 状态目录 behavior-learning/：
Linux 默认 /opt/secweaver-agent/state/behavior-learning/；自定义安装根遵循统一布局。
Windows 0.3.38 使用 `data/behavior-learning-windows` 和 SYSTEM/Administrators 受限 ACL；
实际路径与真实平台验收要求见使用指南。
目录 0700、文件 0600，包含 manifest、candidate checkpoint、不可变 baseline、
本机指纹密钥和提交校验信息；不保存未脱敏的完整命令。

状态目录由单一进程持有独占锁。第二实例不能写入；本模块回退原始输出并告警。
检查点默认每 60 秒异步写入：临时文件、fsync、原子 rename、目录 fsync。
候选统计的最近 60 秒可能在崩溃时丢失，只允许延迟完成学习，不允许提前晋级。
活跃基线指针与内容以事务/原子 manifest 提交，保留上一版本供回滚；
损坏/未知版本/校验不一致不加载、不自动重建为已完成状态。

升级后设备身份、指纹和能力版本兼容才复用基线；不兼容时停止过滤并提示重新学习。
audit/eBPF 切换按能力版本分区；缺少等价字段的事件原始输出，不把 unknown 当作相等。
远程策略沿用签名、设备/租户范围、版本校验和灰度；禁止跨主机直接复制学习结果。
本地 standalone 管理使用相同的验证入口，不依赖联网才可停止过滤。

## 9. 资源与性能预算

| 资源 | 默认提案与超限处理 |
|---|---|
| 冻结名单 | 最多 10,000 条；其余候选不晋级、继续原始输出 |
| 候选名单 | 最多 20,000 条；达到上限停止学习新指纹，记录候选溢出 |
| 模块内存 | 合计 64 MiB，含索引、字符串、上下文、摘要和队列 |
| 状态磁盘 | 合计 64 MiB，包含新旧版本、临时文件和检查点；预留原子写空间 |
| 身份校验任务 | 默认 2 个 worker、256 个队列槽；入队失败或超时即原始输出 |
| 数据热路径 | 平均 O(1) 哈希查找；无网络和同步磁盘 IO |

单条事件大小沿用采集器约束；超长/截断事件不学习。
字符串、argv 指纹输入和上下文必须按实际分配字节计费，不能只限 map 条数。
达到内存预算不随机淘汰活跃安全判定；停止新候选/上下文准入并恢复原始输出。
固定基线不可由 runtime 的 LRU 自动扩大或替换。
摘要与状态队列必须有界，失败标记统计不完整，并恢复相应原始输出。
原有磁盘不足策略仍可能影响最终落盘；emit 表示回到原有写入路径，不承诺无限存储。

需基准验证新增 CPU、RSS、P95/P99 延迟、摘要字节和候选高基数攻击场景。
初步验收目标：正常负载新增 CPU 时间不超过原流水线 5%，过滤判定 P99 < 1 ms
（不含已有上下文构建），模块 RSS 不超过预算加明确测量的运行时开销。
这是待验证目标，不是已实现性能。

## 10. 日志、资产与 Skills 契约

原始 exec 保持既有字段；拟增加 event_id、behavior_fingerprint、baseline_id、
learning_state、learning_decision、decision_reason 和 fingerprint_version。
event_id 需包含设备/启动/后端发生标识，可跨上传重试去重，不依赖输出时刻。

拟新增独立 behavior_summary 事件，包含：

- summary_id、device_id、baseline_id、behavior_fingerprint、policy_revision。
- window_start/window_end、first_seen/last_seen、observed_count、suppressed_count。
- original_emitted_count、context_reemitted_count、counter_complete、gap_reason。
- 服务身份摘要、脱敏代表样本、backend、fingerprint_version、reason。

计数只统计唯一源事件，正常完整窗口满足
observed_count = suppressed_count + original_emitted_count。
祖先补发不增加 observed_count，单列 context_reemitted_count；
重试按 event_id/summary_id 去重，失败的输出不得计为成功写出。
摘要不得伪装成一次原始 exec 或借用一个 PID 表示所有执行。

拟新增独立模块日志 behavior-learning.log，用于摘要与模式转换；
它沿用统一权限、缓冲、轮转和磁盘预算，并防止采集自身输出。
ES/Filebeat、SLS/Logtail 及独立 shipper 交付方必须显式增加该日志路由和索引。
发布前将行为摘要映射至独立逻辑资产 host_behavior_summary，并同步公开模板与私有资产包；
Collector 开关启用不能早于下游摘要契约准备完毕。此文不声称上传配置已存在。

健康日志每 5 分钟增加模式、学习进度、名单版本、候选/命中数量、观测/原始/抑制计数、
摘要写入失败、丢事件、上下文淘汰、资源占用和策略回退原因。
业务摘要不塞进单条无限增长的健康快照。
Skills 必须区分原始事件数、摘要条数、代表行为次数和补发上下文。
数据完整性评估应展示 learning 状态和免报时间段，不把缺原始 exec 解释为没有执行。
溯源不得利用摘要代表 PID 构建真实进程边；报告说明已知行为被过滤以及上下文缺口。
减量度量分别统计条数与实际字节，并包含摘要和补发成本。

## 11. 管理流程、灰度与回滚

拟管理能力：查看状态/进度，导出脱敏候选，查看晋级与排除原因，显式重新学习、
停用过滤、撤销名单项、回滚基线、导出变化审计。具体 CLI/API 名称待实现确定，
本文不提供可执行的新命令。

新安装首次启动采集自动进入 learning，保持全量输出；满 24 小时有效观测后冻结合格项并进入 enforcing。
旧安装升级保留原有显式启用策略；主动启用或重新学习从操作生效后开始计时。
业务升级期间原有名单继续精确匹配；变化的行为输出。需要新基线时显式 relearning，
该作用范围恢复全量，替换版完成前不追加未知行为到旧名单。
人工批准也不能绕过始终采集规则。管理员降低阈值或放宽参数掩码必须记录操作者、
策略 revision、生效时间与作用范围，远程操作需签名。

建议先对少量代表性主机启用：完成一天学习后观察一天，再扩大比例。
支持验证阶段 shadow 模式：计算 would_suppress 和预计字节，但仍全量写出；
shadow 为可选灰度工具，默认学习结束无需再等一天才过滤。
误过滤时立即切换 full；旧基线保留只读用于复盘，不要求重启机器或重装 Agent。
切换失败保持原始输出可用并产生状态告警，禁止“控制服务不通就停止采集”。

## 12. 验收、风险与阶段

首期验收必须覆盖：

1. 新安装首次启动采集即自动学习，无需手动启用或等待次日；仅安装未启动不计时。
   正常周期任务学习 24 小时后进入名单；未达阈值任务仍原始输出。
2. 学习期插入 shell、敏感操作和未知上下文，不进入自动免报名单。
3. 名单内父进程执行未知子命令，子事件和可用祖先证据仍可调查。
4. argv 边界、参数、cwd、身份、TTY、程序/父程序、监听根变化分别导致不命中。
5. PID 复用、同 PID 二次 exec、容器重建不继承无关执行身份。
6. 停机/重启/时钟跳变不提前结束学习；重启保持已冻结基线。
7. audit/eBPF 丢事件、状态损坏、写满磁盘、锁竞争、队列拥塞均恢复原始输出。
8. 名单内频率突增及窗口边界突发触发原始输出，不静默裁剪未知事件。
9. 真实 SLS 和 ES 入库摘要，验证计数、去重、Skills 覆盖说明与进程关联。
10. 24 小时压力测试及至少 7 天稳定性观察，确认内存、磁盘与状态文件有界。
11. 签名校验、灰度、撤销、全量回滚和后端切换按状态机执行。
12. 对已知攻击演练比较 full 与 enforcing 的可调查证据，明确记录漏失和剩余风险。

阶段一实现 Linux 学习/匹配、始终采集、状态存储、祖先缓存、摘要及本地管理。
阶段二在发布启用前完成 ES/SLS 路由、资产/Skills 契约和灰度回滚验收。
Windows Sysmon 代码已在 0.3.38 接入；真实平台验收、受控脚本身份与可变参数策略仍是后续工作。

学习模式不能识别所有已存在的入侵，不能提供过滤期间完整的原始历史。
首日全量成本仍存在；若业务主要是变化命令或首期强制保留的脚本，减量可能有限。
先用 shadow 数据计算 eligible_exec 占比及字节收益，决定是否扩大部署。
异常事件不因“太多”而被自动学习，保护调查能力优先于固定减量指标。
