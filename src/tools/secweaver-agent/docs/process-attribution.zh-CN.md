# Linux 进程归属与短命进程证据

**语言：** [English](process-attribution.md) | 简体中文（本文）

Agent 0.3.92 修复监听服务向运行时父进程扩展、PID 复用命中旧缓存及短命进程身份不可读时沿用旧归属的问题。适用于 Linux `audit`、`audit_pid` 的用户态归属，以及 eBPF 辅助 audit 规则的缓存查询；eBPF 执行事件在服务根身份无法确认时保留为未知归属。Windows 采集行为不变。

## 服务归属的含义

`listener_process` / `listener_pid` 表示采集器确认的监听服务上下文，不等同于事件进程的直接父进程；直接父进程仍由 `ppid` 表达。已配置的 Web 网关与 PHP 等关联后端属于显式采集策略，也不能据此断言网关进程直接执行了命令。

例如：

```text
containerd-shim
├── mysqld
└── runc
```

MySQL 服务根只能向已确认的后代传播归属，不能把父 shim 纳入自己的进程树。这里的 runc 是兄弟进程；它的目标容器可能是 MySQL 容器，但这不足以证明 mysqld 发起了调用。Agent 不因进程名是 runc 而将其列为可信或正常任务；本次没有新增容器任务识别或 runc 汇总过滤。

## 身份校验与不确定性

- 归属缓存使用 PID 和启动时间校验进程实例，缓存拥有者及异步任务另外绑定服务根的启动时间。身份检查直接读取 `/proc`，不使用进程信息富化缓存。
- PID、父 PID、祖先和显式关联后端的归属命中都经过身份检查。非有界后端的祖先查询最多检查每条起始链的 64 个节点，并检测循环；有界 audit 的无关事件不遍历祖先。
- 服务根 PID 被重新使用时，已知旧代际的子进程不会通过新的父/根缓存重新获得归属；已经接收的主记录在组装期间身份失效时，仍保留为未知归属。
- 后台安装规则前后检查进程和根身份；旧根失效后，排队任务不能把旧服务归属重新写回。失效归属立即撤销，内核规则仍由原工作协程管理和重试清理。
- 已退出进程只有在存在成功 clone/fork 证据、父 PID 一致、服务根身份有效，并且源事件时间与本地接收时间都满足 5 秒窗口时，才可使用短期关联。重复或更早的 clone 不能刷新该窗口，普通 exec 也不能续期。
- 读取不到身份不代表匹配成功。记录父 PID 冲突时拒绝旧缓存，再尝试可验证的父归属。已跟踪但仍无法确认的事件保留明细，省略 `listener_*`，增加可选字段 `attribution_status: "unknown"`。
- 未知归属事件直接写原始事件输出，不进入执行/文件行为学习，避免空服务名被学入基线或被旧基线过滤。普通已确认事件不增加该字段。

有界 `audit` 的无关主机事件仍在聚合前过滤；所有后端的敏感路径 watch 命中本身也不足以扩大服务采集范围。`audit_pid` 已由 PID/可执行文件规则限定的未匹配事件保留为未知归属。eBPF 已由内核跟踪范围限定的执行事件，在服务根失效时保留明细，不使用该失效归属扩展辅助规则。

父 PID、时间窗和 clone 关联仍受内核事件丢失、读取延迟及进程身份可见性限制，不是完整的历史进程数据库。缺失 fork 或超出窗口时不能承诺重建完整调用链；应同时检查 Agent 的丢失与积压指标。未知归属是证据质量状态，不是风险等级，也不是已确认攻击。

## 升级与灰度验证

使用新版本包升级；不要用 0.3.91 的版本号重新发布修改后的二进制。正常升级重建内存中的进程归属及规则，不自动清空现有学习基线，也不修改已经上传的历史日志。下游应允许可选的 `attribution_status` 字段及缺失的 `listener_*`；旧版本事件没有该字段，不能据此追认旧归属准确。

建议先选择一个 Linux 容器主机灰度，并记录实际后端、版本、进程启动时间和升级前后窗口。需要相应 `/proc` 读取能力，以及既有 audit/eBPF 运行权限；无需为本修复额外开放 Docker 管理 API。

验收包括：

1. 用同一时刻的进程树核实服务根、运行时父进程和兄弟进程，确认兄弟进程不再误标成 Java/MySQL。
2. 在隔离测试服务中验证真实的子进程及多代后代仍能采集，检查短命进程、服务重启和 PID 复用。
3. 检查未知归属记录的命令明细保留，且不带猜测的服务字段；同时确认无关主机事件仍被过滤。
4. 对比 CPU、内存、输出量、采集延迟及 lost/backlog。未知明细增加可能来自旧误归属被纠正，不能直接解释为攻击增加或采集故障。

源码回归可在 Agent 目录执行 `go test -race ./pkg/auditportexecmon`。测试包含合成进程生命周期及真实事件组装/输出链路，不替代目标 Linux 主机上的 audit/eBPF 挂载和灰度验收。

若需要回退，按既有升级恢复流程回到上一完整版本并重建进程跟踪。上一版本仍有本次归属缺陷，应结合原始 PID、PPID 和容器证据解释事件，不能把回退等同于修复仍有效。归属修复稳定后，再独立评估健康检查减频或 runc 首条加汇总策略。
