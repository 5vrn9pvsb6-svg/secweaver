# Linux 进程归属与短命进程证据

**语言：** [English](process-attribution.md) | 简体中文（本文）

Agent 0.3.95 要求 Linux 监听范围内的执行、连接和文件事件在序列化前具备已确认且非空的 `listener_process`。服务根身份无法确认的事件在原始输出、学习和上传之前丢弃；内部只保留 unknown 状态用于生命周期清理。适用于 `audit`、`audit_pid`、eBPF 执行及其辅助 audit 输出，包括原始明细模式、学习关闭/shadow、队列降级和退出前文件事件刷新。本版本在 0.3.94 输出门禁上，修复监听发现、多实例混淆、宽泛兜底归属和短命进程证据丢失，并为 eBPF 传递根进程代际。Windows 采集行为不变。

该规则作用于 Agent 的监听事件日志/标准输出及其后续上传，不修改操作系统的 `/var/log/audit/audit.log`、进程/主机状态/持久化采集器及其他上传来源。被丢弃的明细不会转存诊断日志，也不进入学习计数或摘要。升级前已写入的本地积压仍可能在升级后上传，验收应检查新采集器启动后产生的事件；不会自动删除历史数据。

## 服务归属的含义

`listener_process` / `listener_pid` 表示采集器确认的监听服务上下文，不等同于事件进程的直接父进程；直接父进程仍由 `ppid` 表达。自动关联 Web 后端只接受已验证的后代关系；进程名、命令参数包含后端关键词、相同 exe 或共用宿主机都不足以证明归属。

例如：

```text
containerd-shim
├── mysqld
└── runc
```

MySQL 服务根只能向已确认的后代传播归属，不能把父 shim 纳入自己的进程树。这里的 runc 是兄弟进程；它的目标容器可能是 MySQL 容器，但这不足以证明 mysqld 发起了调用。Agent 不因进程名是 runc 而将其列为可信或正常任务；本次没有新增容器任务识别或 runc 汇总过滤。

## 监听发现与实例隔离

监听发现首先使用 `netstat -tlnp`，在命令失败、缺少 PID 或解析不完整时使用 `/proc/net/tcp{,6}` 和 `/proc/<pid>/fd` 的 socket inode 关联。TCP 表的 inode 固定取第 10 个空白分隔字段，不从末尾倒数；无法确认 socket 持有 PID 时不会因为端口为 22、名称为 systemd/init 就猜成 sshd。

- 每个监听 PID 独立建立根身份，相同 Java/Nginx 可执行文件或相同监听地址不会把独立 PID 合并。初始化从实际 socket 持有 PID 开始，再向后代扩展；不会把所有同 exe 进程播种为一个服务。
- exe 规则仍可降低采集规则成本，但命中只代表候选事件。`audit_pid` 及 eBPF 辅助 audit 同样必须验证真实祖先和根生命周期，不能直接返回 exe 对应的旧标签。
- 不再将独立 PHP-FPM、Gunicorn、Puma 等进程自动挂到第一个 Nginx/Apache。只有可验证的后代能继承该网关；独立后端应按自己的可发现监听根采集。仅使用 Unix socket 或 loopback 的独立后端不会因此自动纳入，此版本没有新增显式代理映射配置。
- 当前自动发现范围仍是 Agent 所在网络命名空间内、经过端口过滤的非 loopback TCP LISTEN；不遍历所有容器网络命名空间，也不将宿主机 NAT/proxy 等同于容器应用根。默认监听重扫为 5 分钟。
- 多个进程共享同一个 socket FD 时，发现源可能只提供一个持有者；其他持有者不会仅因 exe 相同就自动合并。需要验证具体 master/worker 拓扑，不能宣称任意共享 FD 拓扑都覆盖完整。

## 身份校验与不确定性

- 归属缓存使用 PID 和启动时间校验进程实例，缓存拥有者及异步任务另外绑定服务根的启动时间。身份检查直接读取 `/proc`，不使用进程信息富化缓存。
- PID、父 PID、祖先和已验证后代的归属命中都经过身份检查。非有界后端的祖先查询最多检查每条起始链的 64 个节点，并检测循环；有界 audit 的无关事件不遍历祖先。
- 服务根 PID 被重新使用时，已知旧代际的子进程不会通过新的父/根缓存重新获得归属；组装期间身份失效的主记录只在内部标记 unknown，并在输出边界丢弃。
- 后台安装规则前后检查进程和根身份；旧根失效后，排队任务不能把旧服务归属重新写回。失效归属立即撤销，内核规则仍由原工作协程管理和重试清理。
- 已退出进程只有在存在成功 clone/fork 证据、父 PID 一致、服务根身份有效，并且源事件时间与本地接收时间都满足 5 秒窗口时，才可使用短期关联。重复或更早的 clone 不能刷新该窗口，普通 exec 也不能续期。`audit` 和 `audit_pid` 共用源时间证据登记；登记不会将 PID 标成规则已安装，已经退出的 PID 不安装规则。
- 读取不到身份不代表匹配成功。记录父 PID 冲突时拒绝旧缓存，再尝试可验证的父归属。已跟踪但仍无法确认的事件只保留内部 unknown 状态，在序列化前丢弃。
- 未知归属事件不会进入原始输出、执行/文件行为学习或上传，避免空服务名被学入基线或被旧基线过滤。普通已确认事件不增加该字段。
- 成功 fork 证据最多保留 16,384 条，采用 5 秒有效窗口；清理每个窗口至多遍历一次。容量满时拒绝新增历史证明，不能通过无限缓存或安装死 PID 规则换取覆盖；超时、缺失、乱序及身份冲突仍可能造成事件被拒绝。
- eBPF 根 map 和 fork/exec/exit 事件携带 `RootStartTime`：由用户态提供的 `/proc` 启动时间 token，内核原样继承，不能与纳秒时间戳直接比较。未知或旧代际事件不能使用当前同 PID 的根，也不能覆盖或清除替代进程的账本。该字段属于内部协议，未新增上传 JSON 字段。

有界 `audit` 的无关主机事件仍在聚合前过滤；所有后端的敏感路径 watch 命中本身也不足以扩大服务采集范围。`audit_pid` 已由 PID/可执行文件规则限定但无法确认监听根的事件只保留内部 unknown，随后在输出边界丢弃。eBPF 服务根失效的执行事件同样丢弃，不使用该失效归属扩展辅助规则。

父 PID、时间窗和 clone 关联仍受内核事件丢失、读取延迟及进程身份可见性限制，不是完整的历史进程数据库。缺失 fork 或超出窗口时不能承诺重建完整调用链；应同时检查 Agent 的丢失与积压指标。未知归属是证据质量状态，不是风险等级，也不是已确认攻击。

## 升级与灰度验证

使用新版本包升级，不要复用旧版本号发布修改后的二进制。正常升级重建内存中的进程归属及规则，不自动清空现有学习基线，也不修改已经上传的历史日志。0.3.95 收紧了归属判定；历史事件中缺失或错误的标签不会被重写。需要检查当前内存/学习基线是否曾受误归属污染；正常升级不会自动清空已有基线。

建议先选择一个 Linux 容器主机灰度，并记录实际后端、版本、进程启动时间和升级前后窗口。需要相应 `/proc` 读取能力，以及既有 audit/eBPF 运行权限；无需为本修复额外开放 Docker 管理 API。

验收包括：

1. 用同一时刻的进程树核实服务根、运行时父进程和兄弟进程，确认兄弟进程不再误标成 Java/MySQL。
2. 在隔离测试服务中验证真实的子进程及多代后代仍能采集，检查短命进程、服务重启和 PID 复用。
3. 检查缺少已确认监听服务的事件不会出现在原始输出或上传流中，同时确认无关主机事件仍被过滤。
4. 验证同一 exe 的两个独立服务、缺 netstat 时的 IPv4/IPv6 监听发现，以及旧事件延迟到达后的根 PID 复用；确认 `pgrep` 查询等命令不会被当作关联后端。
5. 对比 CPU、内存、输出量、采集延迟及 lost/backlog。日志减量现在同时包含未知归属丢弃和学习过滤；学习计数只覆盖进入该引擎的事件。

源码回归可在 Agent 目录执行 `make check`；针对归属运行 `go test -race ./pkg/auditportexecmon`，针对内嵌对象布局运行 `go test ./pkg/processtracker/ebpf`。Linux 上还会执行生成的 Go 结构与事件解码一致性测试，其他开发平台仅解析对象布局，不能代替内核 verifier/挂载验证。测试包含合成进程生命周期及真实事件组装/输出链路，不替代目标 Linux 主机上的 audit/eBPF 挂载和灰度验收。

若需要回退，按既有升级恢复流程回到上一完整版本并重建进程跟踪。0.3.92/0.3.93 可能重新输出 unknown 事件，回退不会保留本次输出限制。该规则的明确取舍是：即使事件真实来自服务，只要无法确认监听身份，也会丢弃。回退到 0.3.94 会重新引入本次修复的识别缺口。升级须使用包含新 eBPF 对象的完整 Agent 包并重启采集器，不能混用旧对象和新解码器；内部 map 不跨重启复用。
