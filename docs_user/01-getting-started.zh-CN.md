# 01. 快速理解 SecWeaver

**语言：** [English](01-getting-started.md) | 简体中文（本文）

本文用普通运营同学能理解的方式，解释 SecWeaver 是什么、解决什么问题、为什么需要配置 `dataasset`。

本文是可选概念阅读，不是安装前置。希望直接体验时，从[10 分钟快速上手](00-security-operator-quickstart.zh-CN.md)开始；产品价值介绍可按需阅读[平台介绍](14-platform-introduction.zh-CN.md)。

---

## SecWeaver 是什么？

SecWeaver 是一个面向安全运营的 AI 原生安全分析与溯源调查平台。

它的目标不是简单接入一个大模型聊天，而是让大模型可以真正使用你的安全数据：

- 查日志。
- 查告警。
- 查主机行为。
- 查网络连接。
- 查数据库审计。
- 把多份证据关联起来。
- 输出可复核的安全结论。

你可以把它理解成：

```text
安全运营数据资产目录 + 调查剧本 + AI 分析助手
```

---

## 它解决什么问题？

传统安全运营里，一线同学经常遇到这些问题：

1. 日志很多，不知道先查哪个。
2. 不同系统字段不一样，关联困难。
3. WAF、主机、SSH、防火墙、DNS 各查各的，证据链断裂。
4. 经验在个人脑子里，换一个人调查路径就变了。
5. AI 能说思路，但不知道你真实有哪些日志。

SecWeaver 想解决的是：

```text
把“查什么、怎么查、怎么关联、怎么解释”变成可配置、可复用、可审计的流程。
```

---

## 为什么不能只靠大模型自己判断？

大模型知道很多安全常识。例如它知道：

- WAF 告警后要查 Web 访问日志。
- WebShell 可能伴随文件写入和命令执行。
- 横向移动常见于 SSH、RDP、SMB。
- 数据外传要看外连、DNS、流量和数据库访问。

但是大模型不知道你的环境里：

- 实际有哪些日志源。
- 哪些日志源已经上线。
- 字段叫 `src_ip` 还是 `client_ip`。
- WAF 日志在哪个 SLS project。
- SSH 日志来自 SLS、文件还是数据库。
- 哪些 Join 规则在你这里是可信的。
- 默认应该查前后多长时间。

所以 SecWeaver 的设计是：

```text
让配置告诉 AI “有哪些数据、应该怎么查”；
让 AI 负责“理解问题、执行调查、解释证据”。
```

---

## 一次调查是怎么跑起来的？

以“帮我判断这个 WAF 告警是不是打成功了”为例：

```text
1. 用户提出问题
   ↓
2. 系统识别这是告警确认场景
   ↓
3. Scenario Pattern 告诉系统：先查 WAF，再查 Web 访问，再查主机行为
   ↓
4. Fetch Plan 根据配置生成取数任务
   ↓
5. Query Template 去对应数据源查日志
   ↓
6. Evidence 归一化成统一字段
   ↓
7. Correlation Matrix 把 WAF、Web、主机行为关联起来
   ↓
8. AI 基于证据链输出结论：误报 / 疑似 / 成功 / 证据不足
```

这个过程里，大模型不是随便猜，而是沿着你配置好的数据资产和调查剧本工作。

## SecWeaver 里最重要的目录

普通运营同学最需要关注的是 `dataasset/`：

```text
dataasset/
├── assets/             # 逻辑数据资产：这是什么数据
├── connectors/         # 连接器：怎么连接数据源
├── credentials/        # 凭证：密钥放这里，不写明文
├── hosts/              # 主机：重要服务器信息
├── networks/           # 网段：IP 属于哪里、信任级别如何
├── bundles/            # 资产包：某个调查任务需要哪些数据
├── scenarios/          # 调查场景：某类问题先查什么
├── query-templates/    # 查询模板：实际怎么查
└── schema/             # 校验规则
```

---

校验和测试脚本位于仓库根目录下的 `src/dataasset/`，与 `dataasset/` 分开。仓库随附的 `dataasset/` 包含合成示例，使用时默认直接在该目录配置，也可复制到 `dataasset_my/` 隔离使用，准备步骤见[数据源配置](03-configure-data-sources.zh-CN.md)。

## 你作为运营同学主要做什么？

你通常需要做这些事：

1. 新增或修改数据源。
2. 配置数据源连接方式。
3. 确认字段含义和字段映射。
4. 把关键主机和网段登记清楚。
5. 把常用数据源加入合适的资产包。
6. 运行校验脚本，确保配置没问题。
7. 使用 AI 发起调查并复核结果。

## 最小可用路径

首次体验先走[合成数据快速上手](00-security-operator-quickstart.zh-CN.md)，无需接入真实数据。本节面向体验后的生产试点，建议先接入三类数据：

```text
WAF 告警
Web 访问日志
主机命令执行日志
```

这三类数据可以支撑：

- WAF 告警确认。
- WEB 入侵判断。
- 是否打到主机。
- 是否出现命令执行。

之后再扩展：

- SSH 登录日志：判断横向移动和账号失陷。
- 防火墙日志：判断跨网段访问。
- DNS 日志：判断可疑域名访问。
- 网络流量：判断大流量外传。
- 数据库审计：判断敏感数据访问。

---

## 你需要避免的误区

### 误区一：先接所有日志再使用

不需要。先跑通一条关键链路，再逐步扩展。

### 误区二：让大模型自己决定一切

不建议。大模型应该在配置约束内工作，否则容易漏查或臆造。

### 误区三：字段不统一也没关系

不行。字段不统一会直接影响关联。比如一个日志叫 `client_ip`，另一个叫 `src_ip`，需要通过字段映射统一。

### 误区四：配置完不校验

每次修改 `dataasset/` 后都建议运行校验脚本。
