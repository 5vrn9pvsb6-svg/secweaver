# 10. 常见问题 FAQ

**语言：** [English](10-faq.md) | 简体中文（本文）

本文收集普通运营同学在理解、配置和使用 SecWeaver 时最常见的问题。

---

## Q1：SecWeaver 是 SIEM 吗？

不是传统 SIEM。

它更像是：

```text
安全数据资产目录 + 调查编排规则 + AI 分析执行层
```

它可以使用 SIEM、日志平台、数据库、对象存储、主机文件等作为数据源，但它本身的重点是让 AI 能够基于这些数据进行调查和研判。

---

## Q2：为什么要配置 dataasset？直接让 AI 查日志不行吗？

不建议。

因为 AI 不知道：

- 你的日志在哪里。
- 哪些字段表示 IP、主机、账号。
- 哪些数据源已经上线。
- 哪些 Join 规则可信。
- 用什么查询语句。
- 时间范围应该多大。

`dataasset` 的作用就是把这些信息变成机器可读配置。

---

## Q3：Scenario Pattern 是不是限制了大模型？

不是简单限制，而是给大模型提供可靠调查路径。

大模型负责理解问题和解释证据；Scenario Pattern 负责告诉它：

```text
这个场景先查什么、再查什么、默认查多久。
```

如果完全让大模型自己决定，容易出现：

- 漏查关键日志。
- 调查顺序不稳定。
- 臆造不存在的数据源。
- 不同分析师得到不同路径。

所以推荐做法是：

```text
大模型选择或建议场景，Scenario Pattern 约束取数和关联路径。
```

---

## Q4：Asset 和 Connector 有什么区别？

简单理解：

```text
Asset = 这是什么数据
Connector = 怎么连接这份数据
```

例如：

```text
Asset：生产 WAF 告警
Connector：阿里云 SLS 的 project/logstore/endpoint 配置
```

同一个 Asset 可以聚合多个 Connector。例如多台主机的 SSH 日志可以合并成一个 `ssh_auth` 逻辑资产。

---

## Q5：为什么要有 Host 和 Network？

因为很多安全调查不能只看单条日志，还要理解上下文。

Host / Network 可以帮助判断：

- 这台机器属于哪个业务区。
- 是否是数据库服务器。
- 是否暴露公网。
- 访问是否跨网段。
- 是否从 DMZ 进入生产网。
- 是否从普通网段访问高敏感网段。

对于横向移动和数据外传，这些信息非常重要。

---

## Q6：什么情况下需要配置 field_aliases？

当源日志字段名和平台标准字段不一致时，需要配置。

例如标准字段是 `src_ip`，但源日志里叫：

```text
client_ip
remote_addr
ip
source_ip
```

就应该配置字段别名。

否则系统可能无法把不同日志关联起来。

---

## Q7：为什么 validate 通过了，还是查不到数据？

validate 主要检查配置静态正确性，不保证真实数据一定存在。

还需要检查：

- 数据源是否真实连通。
- 查询模板是否正确。
- 时间范围是否有数据。
- 参数是否传对。
- 凭证权限是否足够。
- 日志字段是否和模板一致。

---

## Q8：为什么 AI 说“证据不足”？

可能有两类原因。

### 第一类：确实没有证据

例如攻击请求没有到达后端，或者没有主机命令执行。

### 第二类：数据缺失

例如：

- 主机日志没有接入。
- DNS 日志没有接入。
- 字段映射错误。
- 时间窗不合理。
- Bundle 没包含对应 Asset。

所以看到“证据不足”时，要看 `data_gaps`，不要只看最终结论。

---

## Q9：一个新数据源应该直接设为 active 吗？

不建议。

推荐流程：

```text
discovery → draft → active
```

- `discovery`：新日志格式，还在识别字段。
- `draft`：配置中，待验证。
- `active`：验证通过，可用于正式调查。

---

## Q10：开源项目里可以放 example connector 吗？

可以，但不要放真实密钥。

建议：

- example connector 使用假 endpoint 或示例配置。
- `credentials_ref` 使用示例 vault 路径。
- 明确标注 `status: draft` 或示例用途。
- 不要提交真实 AccessKey、密码、私钥。

---

## Q11：如何判断一个场景的数据源是否足够？

可以按场景检查关键数据源。

例如 S4 告警确认至少需要：

```text
WAF 告警
Web 访问日志
主机命令执行
```

如果要判断攻击是否成功，最好还要有：

```text
主机文件操作
主机外连
```

如果缺少关键数据源，AI 应该输出“无法确认”或“证据不足”，而不是硬下结论。

---

## Q12：为什么要把调查路径写成配置？

因为安全运营需要稳定、可复核、可迭代。

如果调查路径只藏在 Prompt 或某个人经验里，会有几个问题：

- 换人后方法不一致。
- 模型版本变了结果变动大。
- 很难审计为什么查这些数据。
- 很难发现到底缺哪类日志。

写成配置后，可以：

- 统一调查方法。
- 复用最佳实践。
- 让 validate 检查配置。
- 让 AI 输出更稳定。

---

## Q13：我要先接哪些数据源？

建议按价值优先级接入：

### 第一阶段：最小闭环

```text
WAF 告警
Web 访问日志
主机命令执行
```

### 第二阶段：溯源和横向

```text
SSH 登录
防火墙日志
资产清单
```

### 第三阶段：外传和深度确认

```text
主机外连
DNS 日志
网络流量
数据库审计
文件操作
```

## Q14：运营同学需要改 Python 代码吗？

正常情况下不需要。

运营同学主要编辑：

```text
dataasset/assets/*.json
dataasset/connectors/*.json
dataasset/hosts/*.json
dataasset/networks/*.json
dataasset/bundles/*.json
dataasset/scenarios/*.json
dataasset/query-templates/*.json
```

如果只是新增同类数据源，一般只需要改 JSON。

## Q15：如何判断智能体的结论可信？

看三点：

1. 是否列出了具体 evidence。
2. 是否有 `join_edges` 支撑证据链。
3. 是否明确说明 `data_gaps`。

可信的输出应该类似：

```text
因为 WAF 告警和 Web 访问在同一 src_ip、url 和时间窗内命中，
且随后目标主机出现异常命令执行，
所以判断攻击疑似成功。
但没有文件操作日志，因此不能确认 WebShell 是否落地。
```

不可信的输出通常是：

```text
看起来像攻击成功。
```

但没有证据链。

---

## Q16：如果我要贡献新的数据源模板，应该提供什么？

建议至少提供：

- 一个 example Connector。
- 一个 example Asset。
- 对应 Query Template。
- 字段说明。
- 示例日志或脱敏样例。
- validate 通过结果。
- 这个数据源适合哪些场景。

---

## Q17：如何保护敏感信息？

遵守这些原则：

- 不提交真实密钥。
- 不把密钥发给 AI。
- 不在日志样例中保留真实用户隐私。
- 开源前清理公网 IP、内部域名、账号、Token。
- Connector 只保留非敏感连接配置。

---

## Q18：我应该读 `docs_user/` 还是 `docs_dev/`？

如果你是普通用户或运营同学，读 `docs_user/`。

如果你要维护底层实现、修改关联引擎、扩展 Skill、调整 schema，再读 `docs_dev/`。
