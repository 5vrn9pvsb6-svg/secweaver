# Data Source Onboarding FAQ

**Languages:** English (this page) | [简体中文](16-data-source-onboarding-faq.zh-CN.md)

This page gives short answers only. Use these task guides for procedures:

- Complete onboarding and activation: [How to Configure Data Sources](03-configure-data-sources.md)
- Field discovery, parser selection, and aliases: [Log Format Discovery](20-log-format-discovery.md)
- Validation and troubleshooting: [Operations Checks and Troubleshooting](09-operations-troubleshooting.md)

## Where do I start for a new source?

Start with the [end-to-end onboarding workflow](03-configure-data-sources.md#end-to-end-onboarding-workflow).
It covers asset-root selection, credentials, Connector and Asset registration, query
acceptance, activation, and Bundle admission. Use `discovery` for unknown formats and
`draft` for known but unverified formats.

## Should I edit `dataasset/` or copy `dataasset_my/`?

Edit `dataasset/` by default. Copy it to `dataasset_my/` only when you want local isolation,
then set `DATAASSET_ROOT=dataasset_my` consistently for the CLI, Studio, and agent.
Never overwrite an existing `dataasset_my/`, and never commit customer configuration,
credentials, private keys, or encrypted credential files.

## Do syslog, auth.log, or Nginx require Python changes?

No. Select `syslog_auth` or `nginx_combined` in the Asset's `text_parser`. For a new text
format, add a reviewed JSON parser under `dataasset/parsers/` and reference its ID.
Do not edit `ssh_fetch.py` or other Skill runtime code for ordinary format onboarding.

## Does an SLS Asset always need `text_parser`?

No. Inspect a few returned rows first:

- Business fields already at the top level: omit `text_parser`.
- A complete JSON object is embedded in one raw field: use `json_lines` or `json_lines2`.
- The returned value is still a syslog or Nginx line: use the matching parser.

Parser choice is based on the Connector's returned shape, not the producer's original format.

## Are there copyable vendor examples?

Yes. Start under `dataasset/onboarding/examples/`. It contains basic SLS/ES/SSH,
CloudWatch, cloud audit/SIEM, EDR/identity, warehouse, and generic external-connector
examples. Preview before writing:

```bash
.venv/bin/python src/secweaver.py asset apply --output-dir "$DATAASSET_ROOT" \
  -f dataasset/onboarding/examples/vendor-quickstart-cloudwatch.json --dry-run
```

The Studio wizard is at `http://127.0.0.1:8765/onboarding.html`; see the
[UI walkthrough](11-onboarding-ui-walkthrough.md).

## How do I review or roll back generated configuration?

Use `asset apply --dry-run`, `asset diff`, and then `asset apply` as described in the
[complete workflow](03-configure-data-sources.md#5-preview-apply-and-review-generated-configuration).
For rollback, run `asset rollback ... --dry-run` first. Rollback only targets objects
generated by that onboarding file; do not manually delete active production objects.

## What if my `connector_type` is missing from Studio?

Register a config-only type in `dataasset/configure/external-connectors.json` and use the
generic external connector, or implement and validate a Connector plugin. Runtime support,
query key, and executor behavior must be explicit; a dropdown entry alone does not create
a working fetch path. See [External Connector Executors](../docs_dev/05-external-connector-executors.md).

## What if source fields do not match canonical fields?

Keep query templates on real source fields and map returned values to canonical fields with
per-Asset `field_aliases`. Do not make Skills read vendor-specific fields directly. Use the
[field discovery and normalization model](20-log-format-discovery.md#field-discovery-and-normalization-model)
for diagnosis, parser selection, reviewed write-back, and verification.

## What should I do when validation fails?

Run `python3 src/secweaver.py validate --diagnose`, preserve the complete output, and follow
the [validation action plan](09-operations-troubleshooting.md#turn-validation-findings-into-an-action-plan).
Fix P0/P1 issues before activation and rerun both registry validation and the affected
Connector/query test. Empty query results are not successful acceptance.
